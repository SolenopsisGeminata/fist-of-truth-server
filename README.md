# Fist Duel — сервер (счётчик онлайна, регистрация/вход, авторитетный PVE+PVP)

Один небольшой Node.js-процесс делает три вещи:

1. **WebSocket-счётчик** — честно считает открытые вкладки с игрой.
2. **Настоящая регистрация и вход** — HTTP API поверх файловой базы данных
   (`lowdb`, хранит данные в файле `db.json` рядом с сервером). Пароли
   никогда не хранятся в открытом виде — только bcrypt-хеш.
3. **Полностью авторитетный игровой движок** (`game-engine.js`) — **и для
   PVE, и для PVP одинаково**. Сервер — единственный источник истины для
   матча: он хранит руки обеих сторон, их колоды, доски, ману и сам
   считает розыгрыш карт и бой. Разница между режимами чисто в том, кто
   играет за вторую сторону:
   - **PVP** — второй реальный игрок, найденный через матчмейкинг.
   - **PVE** — бот, которого сервер сам разыгрывает функцией
     `aiPlaceCards()` в момент, когда человек завершает свой ход (та же
     схема: разложить доступные по мане карты, при возможности ударить
     заклинанием по сильнейшей угрозе), после чего раунд разрешается
     как обычно.
   В обоих случаях клиент не вычисляет исход сам — он только отправляет
   намерения (`place_card`, `cast_spell`, `sacrifice`, `end_turn`) и
   отрисовывает снимок состояния, который присылает сервер. Это
   одновременно и архитектура, и античит: подделать ход, руку или бой с
   клиента невозможно — клиент их просто не считает. **Важное следствие:
   PVE больше не работает офлайн** — как и PVP, ему нужен настроенный и
   доступный сервер.

## Файлы

- `server.js` — HTTP API, WebSocket, матчмейкинг, PVE-бот, персистентность.
- `game-engine.js` — сама игровая логика PVP (без внешних зависимостей,
  чистые функции). `server.js` его импортирует.
- Оба файла нужно деплоить вместе.

## Локальный запуск

```bash
cd server
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`. Проверка:
`http://localhost:3000/` → должно вернуться "Fist Duel server is running."

После первой регистрации/первого матча рядом появится файл `db.json` —
это база данных: пароли (bcrypt-хеши), колоды игроков (`decks`) и
состояние каждого сыгранного или идущего PVP-матча (`matches`, включая
руки обеих сторон — сервер должен их знать, чтобы проверять ходы; от
соперника они по-прежнему скрыты, скрытность обеспечивается на уровне
рассылки, а не хранения).

## HTTP API

| Метод | Путь | Тело запроса | Ответ |
|---|---|---|---|
| POST | `/api/register` | `{ "username", "password" }` | `201 { ok: true }` или `4xx { error }` |
| POST | `/api/login` | `{ "username", "password" }` | `200 { ok, token, username }` или `401 { error }` |
| GET  | `/api/me` | заголовок `Authorization: Bearer <token>` | `200 { username }` или `401` |
| POST | `/api/logout` | заголовок `Authorization: Bearer <token>` | `200 { ok: true }` |
| GET  | `/api/deck` | заголовок `Authorization: Bearer <token>` | `200 { counts }` — сохранённая колода игрока |
| POST | `/api/deck` | `{ "counts": {"c1":2, "s1":1, ...} }` + токен | `200 { ok: true }` или `400` (>30 карт) |
| GET  | `/api/matches/:matchId` | — | `200` с полным сохранённым состоянием матча, или `404` |

Правила: имя игрока — 3–20 символов и уникально (без учёта регистра),
пароль — минимум 4 символа. Колода теперь привязана к аккаунту на
сервере (не к `localStorage` браузера) — именно её сервер использует,
чтобы построить настоящую колоду и руку при старте PVP-матча. Игра
сохраняет колоду туда автоматически при нажатии «Сохранить» в
конструкторе колоды.

## Протокол WebSocket-сообщений для PVE/PVP (для справки)

Клиент → сервер: `start_pve` (мгновенно создаёт матч против бота, без
очереди), `find_match`, `cancel_search`, `place_card`, `move_unit`
(перестановка ещё не разыгранной карты), `return_to_hand` (вернуть в
руку карту, выставленную в этой же фазе подготовки — мана
возвращается полностью, как будто её не выставляли),
`cast_spell`, `sacrifice`, `end_turn`, `leave_match`, `resume_match`.
Действия в матче (`place_card`/`cast_spell`/`sacrifice`/`end_turn`/
`leave_match`) несут `matchId` и `username`.

Сервер → клиент: `count`, `searching`, `match_found` (несёт `mode:
'pve'|'pvp'`, чтобы клиент знал, как подписать соперника), `state_update`
(снимок состояния под конкретного игрока — своя рука видна полностью,
чужая — только количеством карт), `resolution` (после того как оба
завершили ход: список событий боя для анимации + финальный снимок),
`action_rejected` (нелегальное действие — не хватает маны, чужая
карта, занятый слот и т.п.), `opponent_disconnected`/
`opponent_reconnected`/`opponent_left` (для PVE не приходят — боту
некуда отключаться), `resume_failed`.

Проверка легальности действий — это `game-engine.js`: он и есть
единственное место, где решается, сколько стоит карта, что можно
атаковать и когда наступает бой. Клиенту нечего подделывать, потому
что ему нечего считать. Это одинаково верно для PVE и PVP — единственная
разница в том, кто присылает действия для второй стороны: настоящий
клиент по сети или `aiPlaceCards()` прямо внутри обработчика `end_turn`.

## Развёртывание (бесплатные варианты)

Нужен хостинг с долгоживущим процессом (не serverless-функция) и
поддержкой WebSocket + постоянного диска для файла `db.json`.

### Render.com
1. Зарегистрируйтесь, создайте **Web Service** из репозитория с папкой `server/`.
2. Build Command: `npm install`
3. Start Command: `npm start`
4. **Важно для сохранности базы**: на бесплатном плане Render диск
   эфемерный — при передеплое `db.json` обнулится (а с ним и все
   аккаунты, колоды и история/состояние матчей). Если это критично,
   добавьте Render Disk (платный) в настройках сервиса и укажите
   переменную окружения `DB_PATH=/data/db.json`, примонтировав `/data`
   как персистентный диск. Для теста/пет-проекта эфемерность обычно не
   страшна — просто знайте про это ограничение.
5. После деплоя получите адрес вида `your-app.onrender.com`.

### Railway.app / Fly.io
Аналогично — грузите папку `server/` целиком (оба `.js`-файла), команда
запуска `npm start`, при необходимости постоянного диска — используйте
volume-опции сервиса.

## Подключение игры к серверу

В файле `fist-duel.html` найдите:

```js
const GAME_SERVER_HOST = 'YOUR-SERVER-URL-HERE';
```

и впишите хост без протокола, например:

```js
const GAME_SERVER_HOST = 'your-app.onrender.com';
```

Игра сама соберёт из этого и `https://` (для регистрации/входа/колоды),
и `wss://` (для счётчика онлайна и PVP) адреса. Пока хост не указан,
кнопки входа, регистрации и PVP будут честно показывать «сервер не
настроен», без фейковых успехов.
