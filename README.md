# Fist Duel — сервер счётчика онлайна

Крошечный сервер на Node.js. Он не хранит вообще ничего в базе — просто
держит список открытых WebSocket-соединений и рассылает всем текущее
количество, когда кто-то подключается или отключается. Это и есть
«честный» онлайн-счётчик: реальное число открытых вкладок с игрой.

## Локальный запуск (проверить, что всё работает)

```bash
cd server
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`. Откройте в браузере
`http://localhost:3000/` — должна появиться строка
"Fist Duel online-counter server is running." — значит сервер жив.

## Развёртывание (бесплатные варианты)

Нужен хостинг, который держит **долгоживущий процесс** (не просто
serverless-функцию) и поддерживает WebSocket. Подойдёт один из:

### Render.com (проще всего)
1. Зарегистрируйтесь на render.com, создайте новый **Web Service**.
2. Загрузите содержимое папки `server/` в свой git-репозиторий (GitHub/GitLab) и подключите его, либо используйте "Deploy from a public repo".
3. Build Command: `npm install`
4. Start Command: `npm start`
5. После деплоя Render выдаст адрес вида `https://your-app.onrender.com`.
   Для WebSocket используйте `wss://your-app.onrender.com` (замените `https` на `wss`).

### Railway.app / Fly.io / Glitch
Аналогично: загружаете папку `server/`, задаёте команду запуска `npm start`,
после деплоя копируете выданный публичный адрес и меняете схему на `wss://`.

## Подключение игры к серверу

В файле `fist-duel.html` найдите строку:

```js
const ONLINE_SERVER_URL = 'wss://YOUR-SERVER-URL-HERE';
```

и замените на реальный адрес вашего сервера, например:

```js
const ONLINE_SERVER_URL = 'wss://your-app.onrender.com';
```

Пока адрес не заменён, игра просто показывает «—» вместо числа —
никакой имитации, только честное «нет данных».

## Важно понимать

Счётчик считает **открытые вкладки с игрой, подключённые к этому
серверу** — то есть реальных людей, у которых сейчас открыта игра
(при условии, что HTML-файл раздаётся с одного и того же места, а не
просто лежит у каждого локально на диске). Если файл открывают локально
с диска, а не через общий сайт, то технически считать он всё равно
будет — WebSocket-соединение из локального файла тоже долетит до
сервера — но это будут именно уникальные открытые сессии игры, не
"игроки в матче" и не что-то более сложное. Расширять логику
(разделять по матчам, комнатам и т.д.) можно поверх этого же сервера.
